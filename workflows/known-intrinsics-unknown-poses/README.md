# Known intrinsics, unknown camera poses

**Use case:** 5–30 photos taken with the *same calibrated camera*, moved freely between shots. The scene stays stationary. Intrinsics are fixed; camera positions/rotations are recovered from the images.

## Inputs

- `calibration/olympus_intrinsics.json` generated by `scripts/calibrate_camera.py`.
- Images in `data/known-intrinsics/images/` at **the same resolution, lens focal length and focus setting** as calibration.

## What works now

Our existing `python run.py --images data/known-intrinsics/images --output output/known-intrinsics --colmap-only` performs *uncalibrated-initialized* PyCOLMAP reconstruction. It **does not yet ingest the calibration JSON**. Running that command is a baseline, **not** the calibrated workflow.

## Planned calibrated workflow (not implemented yet)

1. Read the calibration JSON, extracting `fx, fy, cx, cy` and lens distortion. Match OpenCV distortion ordering and a supported COLMAP camera model.
2. At feature-extraction/database creation, supply this camera's actual intrinsics instead of `SIMPLE_RADIAL` with guessed focal length.
3. Keep intrinsics fixed (or tightly constrained) in bundle adjustment; solve only camera poses and 3D structure.
4. Write a standard COLMAP `images/`, `sparse/0/` dataset; pass it to the gsplat trainer using `--skip-colmap`.
5. Compare registered image count and geometric matches with the baseline using the **same** photo set.

The CLI below is **proposed**, not yet supported:

```powershell
python run.py --images data/known-intrinsics/images --output output/calibrated --calibration calibration/olympus_intrinsics.json --colmap-only
```

**Limitations:** Knowing intrinsics will not create visual correspondences on blank surfaces, and freehand monocular reconstruction still lacks absolute metric scale. With just 2–5 views, use strongly overlapping, sharp, textured images and sufficient translation. Investigate feature matching / pair initialization failures before assuming calibration alone will fix them.
